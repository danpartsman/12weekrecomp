# External Connections module (TEST)

Provider protocol adapters live in `src/WebRecomp.ExternalConnections`, an independent .NET class library with no dependency on the fitness engine, web UI, or database. Fitdays is the first adapter. Host orchestration, encrypted storage, background scheduling, and measurement mapping live together under `WebRecomp.Web/Services/ExternalConnections`. Future providers need their own adapter and mapping; supported provider settings are maintained through Administration without editing code.

Routes: `/ExternalConnections` (Profile → Device integrations), `/Fitdays` (connect, preview and select scale profile), `/AdminExternalConnections` (Administration → External connections). All actions and background syncing require the Azure application name `recomp-test`, read server-side from WEBSITE_SITE_NAME. LIVE cannot enable the feature through a host header.

Apply idempotent migration `database/045_external_device_connections.sql` before deploying the host. TEST CI runs the migrator in App Service's configured SQL authentication context without changing permissions or existing measurements. LIVE workflow is unchanged.

Connecting initially uses a 20-minute owner-bound preview in server memory. Saving requires additional explicit consent and persists the selected person ID plus encrypted email, provider password hash and token in `app.DeviceConnections`. The plaintext password is never persisted. ASP.NET Data Protection binds the ciphertext to user ID, client ID and provider. App Service's default persistent Data Protection key ring must remain available across deployments; losing keys requires reconnecting. No credentials are shown in Administration. Provider HTTP logging is disabled because tokens appear in query strings.

Automatic sync checks due connections every minute while the App Service process is running; the default provider interval is 60 minutes. The hosting plan should have Always On enabled for unattended scheduling. Expired provider sessions trigger one automatic login using the saved encrypted password hash. Changed/revoked provider credentials require reconnecting. Disconnect clears the saved credential and pauses syncing, while retaining imported measurements. Manual sync is rate limited. A database lease prevents simultaneous workers from importing the same connection.

Imports use the client's time zone and active program, preserve manual measurement days, and retain provider record IDs to skip repeats. Editing imported body measurements in Daily Entry creates a separate manual override; saving unrelated daily fields keeps an unchanged device reading intact. Imported records are not deleted if subsequently removed at the provider. Body-fat and subcutaneous-fat percentages become fractions; `rosm` and `vwc` percentages become skeletal-muscle and body-water pounds. These mappings match the user's verified Fitdays screenshot and existing manually recorded values. Generic `rom` is not substituted for skeletal muscle. Administration can disable body composition or configure mass units for future imports; existing imported records are preserved.

Protocol source: https://github.com/roquerodrigo/fitdays-api (MIT). Login: POST api/users/login; sync: POST api/sync/syncFromServer. Date bounds use start_time newest and end_time oldest. Regional redirects are bounded and allowlisted; responses are limited to 2MB. Settings allow history of 1–90 days and sync interval of 15–1440 minutes. This community-documented protocol can change upstream.
